# M8 두 번째 팩 제작에서 확인한 제약

M7 리뷰 수정 커밋 `6f5051d` 이후 manor 제작에는 엔진·도구를 수정하지 않았다. 아래 사항은 플러그인이나 콘텐츠 구성으로 해결했고, 후속 엔진 설계 검토 대상으로만 남긴다. MVP 밖의 메뉴·플러그인 씬·공유 팩은 구현하지 않는다.

| 하려던 것 | 막힌 이유 | manor의 우회 | 엔진에 필요한 것 |
|---|---|---|---|
| 단서 플래그 다섯 개를 합산하고 수첩에서 현재 개수와 내용을 표시 | 기본 조건은 개별 플래그/변수 비교이며 text는 변수 치환을 지원하지 않음. 공개 상태 API에도 선언 목록 조회가 없음 | evidence 플러그인이 팩의 다섯 플래그를 직접 조회. `x_enough_clues`로 합산 조건, `x_review_clues`의 showText로 개수·수집한 기록 표시. 별도 카운터를 저장하지 않아 중복 조사에 안전 | 플러그인 없이 필요하다면 선언된 플래그 묶음의 집계 조건·표시 기능. 현재 API로 충분하므로 이번 엔진 변경 불필요 |
| 한 NPC가 배회하다가 확인 키로 대화 | 페이지당 trigger 하나이며 parallel과 action을 동시에 지정할 수 없음. 대화 중 경로 정지 정책도 없음 | 대화하는 정원사 무진은 고정 위치, 별도 통행 허용 관리인은 parallel 배회. 중요한 조사 위치를 가리지 않음 | 같은 객체의 복수 트리거 또는 경로와 상호작용의 분리 및 대화 중 경로 정지 정책 검토 |
| 문마다 방 이름을 화면에 상시 표시 | 지원 Tiled objectgroup은 point markers뿐이고, 문자 표지 렌더/방 이름 UI가 없음 | 입장 대사와 현관홀 안내판에 좌·우·위 문과 방 이름 안내. 금색 바닥으로 출입 위치 표시 | 데이터 기반 표지/방 이름 표시 또는 이미지 표지 사용. Tiled text 지원은 새 명세가 필요 |
| 결말 후 전용 결과 화면과 다시 시작 버튼 | API v1은 플러그인 씬이 없고, stop은 현재 인터프리터만 끝냄 | finished와 결말 플래그로 대화를 후기 페이지로 전환하고 정문에서 결말 재열람. 새 조사/이어하기는 기존 부팅 선택지 사용 | 후속 씬/게임 종료 API와 결과 화면. MVP 밖이므로 현재는 콘텐츠로 종결 |
| JSON 시나리오 안에서 저장 후 재부팅까지 검증 | 현재 정식 시나리오 단계에 저장 데이터 관찰·재부팅이 없고 Node 시나리오의 save 포트는 빈 함수 | 콘텐츠 시나리오에서 save 지점 실행, 별도 헤드리스 테스트에서 실제 save 포트를 캡처하고 loadSave로 복원. 브라우저 새로고침·이어하기도 직접 검증 | 저장 결과 단언과 재부팅 시나리오 단계 검토. 엔진 코어보다 테스트 러너의 확장 대상 |

폰트는 §14에 따라 팩에 복사했다. 도구의 팩 ID 인자 추가는 첫 커밋에서 마쳤으며 manor 생성은 `npm run fonts -- manor`로 재현한다. 480×270, 맵 경계 클램프, 작은 축 중앙 배치, 1920×1080의 4배 확대는 기존 엔진으로 처리한다.

확인 결과: `npm run check`의 191개 단위 테스트, demo 8개·manor 18개 시나리오, 두 팩 빌드 통과. 개발 서버와 manor 정적 빌드의 Chromium 실행에서 480×270/4배 확대, 자동 입장, 네 방 왕복, 다섯 단서, 공개 결말, 실제 저장 후 새로고침·이어하기를 확인했다. 실제 읽기 속도에 따른 플레이 시간은 개인차가 있으며 5~10분은 콘텐츠 분량 기준 예상치다.
